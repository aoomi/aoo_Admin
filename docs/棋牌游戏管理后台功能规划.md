# 棋牌游戏管理后台功能规划

## 1. 建设目标

管理后台是玩法、房间、规则、流程、算分、UI、资源和发布版本的统一管理入口。运营人员应通过可视化表单、勾选、下拉选择、复制模板和上传资源完成日常工作，不需要修改前端或后端代码。

后台展示的“人看配置”和服务端使用的“机器配置”必须来自同一数据模型。后台保存草稿，发布系统校验并生成不可修改的版本快照，前后端只读取已发布版本。

## 2. 用户与权限

### 2.1 用户管理

- 管理员账号创建、停用、重置密码和强制退出。
- 姓名、部门、联系方式和账号状态。
- 登录失败限制、验证码、双重验证和登录设备管理。
- 测试、预发布和生产环境账号隔离。

### 2.2 角色权限

建议预设以下角色：

- 超级管理员：系统配置和全部权限。
- 产品负责人：玩法、规则和发布审批。
- 运营人员：创建玩法草稿和配置可见内容。
- UI 资源人员：上传图片、音频、动画、Prefab 和 Bundle。
- 测试人员：测试环境发布、用例执行和验收。
- 客服人员：玩家、房间、战绩和亲友圈查询。
- 财务人员：房卡、费用、奖励和账务查询。
- 审计人员：只读查看操作记录和发布历史。

权限必须细分为查看、新建、编辑、复制、提交、审核、发布、停用、回滚和导出，不能只区分“管理员”和“普通用户”。

## 3. 首页工作台

- 待审核玩法和待发布版本。
- 配置校验失败和前后端能力不一致提醒。
- 当前在线人数、房间数和各玩法使用情况。
- 服务异常、资源下载失败和协议错误告警。
- 最近发布、回滚、停用和高风险操作。
- 常用入口：复制玩法、创建房间方案、上传资源和查看测试结果。

## 4. 玩法目录

### 4.1 玩法总表

用于让人员清楚查看系统支持的全部玩法，至少包含：

- 玩法编号和名称。
- 四类固定牌类：`Mahjong`、`Poker`、`LongCard`、`WordCard`。
- 玩法族。
- 全国、省、市三级范围，其中地区只维护省和市。
- 可用客户端、最低客户端版本和协议版本。
- 当前草稿版本、已发布版本和启停状态。
- 创建人、修改人、审核人和发布时间。
- 房间方案、规则方案、流程方案、算分方案、结算方案和 UI 方案引用。

全国玩法不通过前端文件夹判断，由玩法配置和地区范围决定。全国玩法可以设置为所有城市可见，也可以指定排除地区。

### 4.2 新增和复制玩法

- 从空白玩法创建。
- 从相同牌类、玩法族或地区玩法复制。
- 只复制选中的规则，不强制复制 UI 和地区。
- 复制后自动生成新的玩法编号。
- 使用向导依次选择牌类、玩法族、地区、房间、规则、算分、UI 和发布范围。
- 页面始终显示完成进度和未完成项目。

## 5. 地区管理

- 全国、省、市三级树形管理。
- 省市名称、行政编号、排序和启停状态。
- 玩法在全国、省、市的可见范围。
- 公共玩法继承和地区覆盖。
- 同一玩法禁止产生相互矛盾的地区配置。
- 城市未配置独有玩法时，自动显示已发布的全国公共玩法。

## 6. 房间配置

### 6.1 公共房间能力

公共基础能力固定由系统提供，不要求每个玩法重复配置：

- 创建、进入、退出和解散房间。
- 断线重连、托管和网络状态。
- 玩家头像、基础信息和亲友圈归属。
- 文字聊天。
- Emoji 表情和魔法表情，可选择两套资源方案。
- 战绩、回放和基础结算流程。

### 6.2 房间进度方案

- 按局数。
- 按时间。
- 按圈，一人完成一次庄家为一圈。
- 所有玩家使用统一局数或统一时间。
- 玩家从坐下开始单独计算自己的局数或时间。
- 中途加入、离开、重连和换座时的进度处理。
- 房间人数、旁观、准备、开局条件和超时参数。

### 6.3 创建房间字段

- 字段名称、说明和排序。
- 单选、多选、开关、数字、下拉和文本控件。
- 默认值、最小值、最大值和可选项。
- 是否显示、是否可修改、是否必选。
- 默认启用但不显示。
- 根据其他选项动态显示或隐藏。
- 根据地区、玩法、亲友圈和用户权限覆盖默认值。
- 预览玩家实际看到的创建房间页面。

## 7. 规则组件中心

规则全部采用受控插拔组件，后台只允许选择后端已经注册并且前端具备对应能力的组件。

### 7.1 组件分类

- 房间规则 `RoomRules`。
- 玩法规则 `PlayRules`，例如换三张、定缺和报叫。
- 流程规则 `FlowRules`，例如庄家先报叫或闲家先报叫。
- 算分规则 `ScoreRules`，例如清一色、七对、飘分和封顶。
- 结算规则 `SettlementRules`。
- 特殊扩展规则 `ExtensionRules`。

### 7.2 组件信息

- 全局唯一规则编号。
- 中文名称、说明和帮助示例。
- 所属牌类和支持的玩法族。
- 执行阶段和优先级。
- 可配置参数、默认值和范围。
- 必须依赖的组件。
- 禁止同时使用的互斥组件。
- 支持的服务端、客户端和协议版本。
- 前端按钮、弹窗、Prefab、Bundle 和结算字段要求。
- 当前状态：开发中、可测试、可发布、已停用。

### 7.3 玩法组件编排

- 拖放或勾选规则组件。
- 自动补齐必需依赖。
- 实时提示互斥和顺序错误。
- 按执行阶段展示完整规则链。
- 显示规则最终生效值和继承来源。
- 支持保存为规则模板。
- 支持比较两个玩法的规则差异。

## 8. 流程配置

- 等待、准备、定庄、发牌、玩法准备阶段、正式出牌、小结算和结束状态。
- 每个阶段的进入条件、完成条件、超时和超时策略。
- 阶段顺序、可跳过条件和中断处理。
- 庄家优先、闲家优先、顺序执行和同时选择。
- 换三张、定缺、报叫、飘分等组件插入的阶段。
- 流程图可视化预览。
- 禁止后台创建服务端未注册的新状态。

## 9. 算分配置

- 玩法规则与算分规则分开管理。
- 牌型、番型、基础分、番数、倍数和附加分。
- 飘分、包赔、封顶、保底和特殊奖励。
- 规则叠加、互斥和优先级。
- 按人数、房间方案和地区设置差异值。
- 输入标准牌例，预览算分明细和最终结果。
- 每项得分必须能显示来源，不能只显示最终总分。
- 发布前自动检查重复计算、无限叠加和无法封顶。

## 10. 结算配置

- 按 `Mahjong`、`Poker`、`LongCard`、`WordCard` 管理结算方案。
- 小结算与大结算分开选择。
- 公共结算基础数据与玩法独有字段分离。
- 选择结算 Prefab、样式包和字段模板。
- 配置字段名称、顺序、显示条件、格式和数据来源。
- 玩家明细、赢家标识、房主、庄家、分数和统计项目。
- 结算预览和模拟数据预览。
- 结算展示组件只能读取结果，不能修改后端得分。

## 11. UI 与资源管理

### 11.1 UI 方案

- 登录、大厅、亲友圈、创建房间、房间、玩法和结算 UI 方案。
- 方案编号、支持方向、设计分辨率和安全区。
- 统一以 `1280×720` 横屏设计基准进行检查。
- 页面、弹窗、按钮、字段和动作绑定关系。
- 不同地区只保存独有 UI，公共 UI 统一引用。

### 11.2 Prefab 与 Bundle

- Creator `3.8.8` 原生 Prefab 登记。
- Prefab 路径、UUID、Bundle、依赖和版本。
- 公共、牌类、Packs 和玩法独有资源分类。
- 显示资源重复引用、循环依赖和 Bundle 过细告警。
- 规则组件自动关联所需 Prefab 和 Bundle。
- 发布前检查文件存在、组件绑定和按钮动作。

### 11.3 图集和静态资源

- 图片、图集、字体、音频、Spine 和其他动画资源上传。
- 资源用途、所属模块、版本、大小和引用关系。
- 图片尺寸、透明度、压缩格式和平台兼容检查。
- 位图字体与贴图关联检查。
- 快捷语音支持后台编辑文字并上传声音文件。
- Emoji 和魔法表情支持两套或多套资源方案选择。
- 未引用、重复、超大和缺失资源提示。

## 12. 下载与预加载配置

- 主包、登录、大厅、亲友圈、房间、牌类和玩法 Bundle 分组。
- 登录时预下载大厅主界面。
- 进入大厅后后台下载常用公共资源和亲友圈资源。
- 玩家点击优先级高于后台预下载，暂停或降速非必要任务。
- 进入房间前下载房间公共资源和当前玩法必要资源。
- 牌桌、牌面颜色等可进入房间后按需下载的装饰资源单独管理。
- 配置 Wi-Fi、移动网络、失败重试、断点续传和缓存策略。
- 显示真实文件数量、字节数和百分比，禁止假进度条。
- 下载少于展示阈值时直接过渡，不出现短暂闪屏。

## 13. 亲友圈管理

- 亲友圈创建、停用、解散和基础资料。
- 圈主、管理员、成员和黑名单。
- 亲友圈可用玩法和房间模板。
- 强制默认规则、允许修改规则和隐藏规则。
- 房费、权限、开房限制和活动时间。
- 快捷文字语音方案和表情方案。
- 战绩、统计、异常房间和操作审计。

## 14. 玩家、房间与战绩运营

- 玩家账号、状态、设备、登录记录和风险标记。
- 当前在线状态和所在房间。
- 房间号、玩法版本、玩家、进度和服务节点。
- 房间解散和异常处理必须经过权限及二次确认。
- 战绩、结算明细、操作回放和规则版本查询。
- 客服只能执行授权操作，不能直接修改牌局结果。

## 15. 配置校验中心

每次提交审核和发布必须执行：

- 必填字段和参数范围检查。
- 规则依赖、互斥和执行顺序检查。
- 房间、流程、算分和结算完整性检查。
- 前后端规则注册一致性检查。
- UI、Prefab、Bundle、图片、字体和音频存在性检查。
- 协议版本和最低客户端版本检查。
- 地区继承和覆盖冲突检查。
- 资源大小、重复依赖和下载顺序检查。
- 标准牌例与自动规则测试。

校验结果需要提供中文说明、影响范围和处理建议，不能只显示程序错误码。

## 16. 审核、发布与回滚

### 16.1 状态流程

```text
草稿
→ 待审核
→ 审核通过
→ 测试环境发布
→ 自动测试
→ 预发布灰度
→ 生产发布
→ 已停用或已回滚
```

### 16.2 发布要求

- 草稿允许修改，已发布版本禁止覆盖。
- 每次发布生成新版本号和完整快照。
- 显示本次变更与上个版本的差异。
- 高风险变更必须双人审核。
- 支持定时发布、灰度范围和快速停用。
- 新版本只影响新创建的房间。
- 已创建房间固定使用创建时版本直至结束。
- 回滚实际是重新启用历史稳定版本，不删除历史数据。

## 17. 测试中心

- 配置校验测试。
- 标准牌例和算分测试。
- 流程状态测试。
- 创建、进入、退出、解散和重连测试。
- 登录、大厅、亲友圈和子游戏端到端测试。
- 按钮、弹窗、背景、适配和资源缺失检查。
- 多客户端版本协议兼容测试。
- 压力测试和长时间稳定性测试结果。
- 每个版本的通过项、失败项、负责人和修复状态。
- 未通过关键测试的版本禁止生产发布。

## 18. 监控与告警

- 在线玩家、活跃房间和各玩法使用量。
- 登录、创建房间、加入、出牌、重连和结算成功率。
- 平均延迟和高分位延迟。
- CPU、内存、垃圾回收、线程和房间队列长度。
- 数据库、Redis、消息队列和网关状态。
- 重复请求、重复结算和重复扣费拦截。
- 客户端资源下载失败和 Bundle 加载失败。
- 告警分级、通知对象、确认、处理和恢复记录。

## 19. 操作审计与安全

- 登录、查询、编辑、审核、发布、停用、回滚和导出全部留痕。
- 记录操作人、时间、IP、设备、修改前后值和审批信息。
- 密码、Token、证书和密钥不得明文显示或导出。
- 生产高风险操作需要二次确认和双人审批。
- 敏感玩家数据按角色脱敏。
- 审计记录禁止普通管理员删除。

## 20. 数据导入导出

- Excel 只作为查看、批量录入和导出工具，不作为运行时数据源。
- 导入前显示差异预览和错误位置。
- 导入数据必须经过与后台编辑相同的校验流程。
- 支持玩法、规则、房间、算分和地区模板导出。
- 人看表、后台数据库和机器配置必须可通过唯一编号逐项对应。
- 禁止直接上传 Excel 覆盖生产已发布版本。

## 21. 用户操作体验

考虑到主要使用者可能不懂代码，后台必须做到：

- 全中文字段名称和通俗说明。
- 专业编号默认收起，需要时再展开。
- 复杂配置采用分步向导，而不是一次展示巨大表单。
- 每个选项显示用途、默认值和实际效果。
- 可视化预览创建房间、流程、算分和结算页面。
- 提供复制模板、恢复默认值和撤销未发布修改。
- 错误提示说明“哪里错、为什么错、怎么处理”。
- 危险操作明确展示影响范围。
- 自动保存草稿，避免误关页面丢失配置。

## 22. 首期开发优先级

### 第一阶段：可配置和可发布

- 用户、角色和权限。
- 玩法总表与地区管理。
- 房间、玩法、流程和算分配置。
- 规则组件中心。
- 草稿、审核、发布快照和回滚。
- 配置校验和操作审计。

### 第二阶段：前后端资源联动

- UI、Prefab、Bundle 和静态资源管理。
- 结算方案。
- 下载与预加载配置。
- 前后端能力一致性检查。
- 自动规则测试和端到端测试结果。

### 第三阶段：完整运营平台

- 亲友圈、玩家、房间和战绩运营。
- 灰度发布、监控、告警和风险控制。
- 财务、房卡、奖励和对账。
- 数据分析和运营报表。

## 23. 开发红线

- 后台不得直接修改正在进行房间的规则。
- 后台不得绕过服务端校验直接发布自由 JSON。
- 玩法名称、地区和 UI 不得代替稳定的唯一编号。
- 已发布版本不得覆盖或删除。
- 前端、后端、管理后台和人看表不得维护互相独立的规则定义。
- 不得让运营人员通过修改代码、数据库或服务器文件完成日常配置。
- 后台显示成功必须代表配置已校验、已持久化并且可以追溯，不能只修改页面状态。
